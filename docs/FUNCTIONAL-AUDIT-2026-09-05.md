## Подтверждённые проблемы и рекомендации

### A01 · P0 · Текущая кампания не переживает перезагрузку

**Воспроизведение:** выбрать Cinder Hollow в launcher → увидеть текст `The Falling Star` и seeded graph → обновить страницу `#/free-form`. После загрузки остаётся ноль графовых узлов и другой текст (`The Stonefang Pass`).

**Причина:** основной Zustand model не сохраняет snapshot; `getInitialState()` восстанавливает встроенный текст и пустые сущности/локации. Архив сессий не является сохранением всего мира.

**Код:** [Model.tsx](../src/model/Model.tsx), [campaignRuntime.ts](../src/model/dnd/campaignRuntime.ts).

**Исправление:** versioned CampaignDocument со стабильным campaignId, текущим текстом, графом и ссылками на вложенные данные; атомарное локальное сохранение, восстановление и резервный экспорт. Для карт и объёмных данных предпочтительно отделить IndexedDB от небольших UI-настроек. Автосохранение должно показывать реальный результат записи.

**Приёмка:** создать/изменить мир → reload → закрыть/открыть вкладку → идентичный snapshot; malformed storage не уничтожает последнюю исправную копию.

### A02 · P0 · Ошибка записи архива приводит к скрытой потере текста

**Воспроизведение:** в отдельном QA-профиле запретить `Storage.setItem` только для `eclipse_dnd_sessions_v1`, выбросив `QuotaExceededError`; завершить сессию без recap. В тесте текст длиной 846 символов стал пустым, на диске осталась одна старая сессия, но UI показал вторую как архивированную.

**Причина:** `persist()` проглатывает исключение; `archiveCurrentSession()` возвращает успех; SessionsPanel безусловно очищает текст.

**Код:** [useSessionStore.ts](../src/store/useSessionStore.ts), [SessionsPanel.tsx](../src/view/dnd/SessionsPanel.tsx).

**Исправление:** возвращать типизированный результат записи и очищать редактор только после подтверждённого сохранения. При quota/permission/corruption сохранять текст, показывать ошибку и предлагать скачать резервную копию. Не удалять данные для освобождения места автоматически.

Смежный code-review finding: Reference Board `saveAsset()` возвращает `true` даже при ошибке `persistBoard`; map store изменяет библиотеку в памяти до подтверждения записи. Для всех хранилищ нужен единый контракт durable success / unsaved / failed и безопасный retry без дублей.

### A03 · P1 · Данные разных кампаний смешиваются

**Воспроизведение:** сохранить `Cinder Hollow — карта` для `location-0`, архивировать главу, открыть другую кампанию через launcher. Та же карта появилась у другой локации `location-0`; архив и название/геометрия atlas draft также остались прежними.

**Причина:** идентификаторы seeded сущностей переиспользуются, а ключи карт, сессий, Reference Board и world events глобальны. У atlas один `eclivarium_living_atlas_draft_v1`. Старт кампании не координирует остальные stores и history.

**Код:** [campaignRuntime.ts](../src/model/dnd/campaignRuntime.ts), [useLocationMapStore.ts](../src/store/useLocationMapStore.ts), [useSessionStore.ts](../src/store/useSessionStore.ts), [LivingAtlasEditor.tsx](../src/view/dnd/LivingAtlasEditor.tsx).

**Исправление:** namespace по campaignId, отдельные mapId/documentId и стабильные entity/location IDs; явное открытие существующей кампании и создание новой. Миграция старых данных должна сохранять их как отдельный legacy project, а не очищать. Архивы/события/DM-контекст и история отмены также обязаны принадлежать кампании.

**Приёмка:** два мира с одинаковыми названиями и локальными индексами не видят карты, реплики, события и архивы друг друга; переключение и reload не меняют принадлежность.

### A04 · P1 · Ctrl+Z в редакторе карты откатывает весь мир

**Воспроизведение:** открыть seeded campaign с четырьмя локациями → открыть Living Atlas → поставить фокус на SVG → Ctrl+Z. В тесте карта получила событие, но основной текст сменился со стартера выбранной кампании на default starter, а список локаций стал пустым.

**Причина:** локальный обработчик делает `preventDefault()`, но событие доходит до document-level обработчика. Последний не проверяет `defaultPrevented`, активный editor/input или scope. Основная history также не сбрасывается согласованно при старте кампании.

**Код:** [LivingAtlasEditor.tsx](../src/view/dnd/LivingAtlasEditor.tsx), [VisualWritingInterface.tsx](../src/view/VisualWritingInterface.tsx), [HistoryModel.tsx](../src/model/HistoryModel.tsx).

**Исправление:** scoped keyboard commands; локальная карта владеет undo/redo при своём фокусе, глобальные команды игнорируют уже обработанное событие и editable controls. Добавить browser regression на карту, текстовое поле, основной редактор и смену кампании.

### A05 · P1 · Рабочее пространство карты слишком тесное

На desktop панель привязана к верхней области графа, а не ко всему окну. При viewport 1416×874 её высота составила 459px, холст начинался на y≈404 и обрезался на y≈471. Рисование в визуально ожидаемой области ниже панели фактически попадает в интерфейс под ней. Есть вложенные вертикальная и горизонтальная прокрутки.

На mobile ширина после стабилизации корректная, но переключатель «Текст сессии / Мир и инструменты» частично закрывает заголовок карты. Центр кнопки закрытия в проверенном состоянии доступен; полной блокировки закрытия не установлено.

**Исправление:** выделенный полноразмерный workspace карты с одним toolbar, холстом как главным содержимым и сворачиваемым inspector; высота относительно viewport, согласованные z-index и safe-area. На телефоне отдельный режим карты вместо наложения нескольких шапок. Проверять реальные hit targets, не только отсутствие overflow.

**Код:** [MapWorkshop.css](../src/view/dnd/MapWorkshop.css), [MapWorkflowPanel.tsx](../src/view/dnd/MapWorkflowPanel.tsx).

### A06 · P2 · Недоработаны геометрия и жизненный цикл редактируемой карты

- Ползунок толщины стены меняет данные, но renderer использует фиксированный `strokeWidth="7"`. Подтверждено в браузере: width 1 → 2 без изменения SVG stroke.
- Комнаты и коридоры рисуются отдельными пересекающимися фигурами. По коду нет boolean union/cutout для проходов; полноценная топология соединений ещё не реализована.
- Сохранённый raster preview не содержит связи с исходным редактируемым atlas document. Один общий draft и ручной project export не заменяют библиотеку редактируемых проектов.
- Лимит восьми карт применяется ко всей библиотеке, а интерфейс показывает счётчик «Карты локации». Это ограничение должно быть явно согласовано с моделью кампаний.

**Исправление:** сначала связать карту с редактируемым документом и исправить толщину; затем соединение комнат/коридоров, вырезание стен под проходы и двери, выделение/перемещение групп. После этого — слои, гексы, освещение и fog. Сохранять собственную реализацию и визуальный язык, не переносить чужой код/ассеты/формат.

### A07 · Release gate · Legal-cleanup и имя не согласованы с shipping code

В текущем checkout launcher, `index.html`, модель и starters продолжают использовать `Eclipse DnD Forge` и защищённые сюжетные/settings names, в том числе Phandalin, Strahd, Barovia, Moradin, Sildar. Это не только исторические записи: строки входят в shipping source и показываются пользователю.

Найдена только root `LICENSE`; `THIRD_PARTY_NOTICES.md`, `docs/CONTENT-LICENSE-POLICY.md` и `tests/ip-boundary.test.mjs` отсутствуют. Поэтому прежний план clean-room/SRD attribution нельзя считать выполненным в этой версии. В тестах Reference Board есть оригинальные fixture names, но это не очищает campaign templates.

**Действие:** восстановить согласованный clean-room slice в текущем checkout, проверить точную атрибуцию SRD 5.1, сохранить upstream MIT LICENSE и отдельно перечислить лицензии кода/правил/оригинального контента. Установить одно текущее имя в UI и документах только в рамках подтверждённого решения по бренду.

Этот аудит не проводил новый trademark search и не даёт юридического заключения. Существующий [trademark report](TRADEMARK-PRELIMINARY-SCREEN-2026-08-20.md) оставляет статус **NOT CLEARED** и коммерческий gate закрытым. Перечень запрещённых имён — regression guard, не юридическая гарантия. [Официальная страница SRD](https://www.dndbeyond.com/srd) не является разрешением использовать любой сюжетный или брендовый материал.

### A08 · P2 · Происхождение imported atlas не переносится в preview

По коду `.eclatlas.json` можно импортировать, но документ не несёт цепочку источника/прав. `useAtlasPreview()` затем выставляет `original`, `ipRisk=none` и очищает source/license поля. Собственный рисунок и импортированный проект становятся неразличимы. Прямой PNG export в atlas не проходит через rights UI Location Map Workshop; это расходится с широким утверждением в прежнем Living Atlas status о gate перед каждым экспортом.

**Действие:** различать original / imported / derived, сохранять provenance при preview/export, не делать положительного утверждения о правах из одного факта рисования или импорта. Предупреждать об отсутствии сведений. Для commercial export нужен единый явный gate; внутренний локальный экспорт не следует выдавать за commercial approval. Это policy/traceability gap, не доказанное нарушение прав конкретным файлом.

### A09 · P2 · AI нуждается в понятном восстановлении после ошибок

Offline-ошибки выводятся пользователю как `Failed to fetch`, а при первой загрузке AI-модуля — с техническим URL chunk. Ошибочный ответ также получает действие «Вставить в сессию». Повторная загрузка однажды упавшего dynamic import в тестовой странице не восстановилась без reload.

По коду DM не передаёт AbortSignal в provider и не предоставляет Stop; у прямых fetch в Ollama/Anthropic нет собственного deadline. Fallback ловит любые ошибки без отдельной семантики отмены. Зависание живого провайдера в этом аудите не воспроизводилось.

**Действие:** timeout + cancel, понятные русские ошибки и Retry, отдельное состояние failed (не обычная реплика), безопасное восстановление deferred modules. Ошибка или отмена не должны менять граф/терять запрос. Отдельные contract tests с mocked streaming, malformed JSON, 401/429/5xx, отменой и медленным ответом.

### A10 · P2 · Документация и интерфейс обещают больше, чем проверено

README утверждает полную русификацию, но starter prose, часть графовых подсказок, `Viewing all 0 Events`, ошибка dice и термины Reference Board остаются английскими. Footer launcher указывает React 19, package.json — React 18.3.1. Разные разделы используют несовместимые светлые/тёмные поверхности и синюю default action рядом с золотой atlas-палитрой.

**Действие:** единые компоненты и словарь, один визуальный стиль для основного рабочего пути, локализация ошибок, корректные empty/loading/error/success/disabled states. Удалить неподтверждённые claims из документации после согласования фактического scope. Не считать написанный status доказательством полноценной пользовательской проверки.

### A11 · P2 · Автоматическое покрытие не ловит основные продуктовые сбои

Часть файлов `*-ui.test.mjs` проверяет наличие строк/обработчиков в исходниках, а не поведение браузера. Эти проверки полезны как контракты, но именно поэтому 79/79 не обнаружили A01–A05. Текущий workflow запускает tests/typecheck/lint/build и bundle budget; отдельного browser E2E и `npm audit` step в нём нет.

**Действие:** добавить малую воспроизводимую browser suite в CI: campaign reload, две кампании, quota/corrupt storage, scoped undo, рисование→сохранение→повторное редактирование, импорт→pins→player handout без GM secrets, узкий mobile viewport, keyboard-only path. Хранить краткие traces/screenshots падений без ключей и содержимого настоящих кампаний.

### A12 · Security Low · Устаревшая транзитивная зависимость

Установлен `postcss-selector-parser@6.1.1` через `tailwindcss@3.4.9` / `postcss-nested@6.2.0`. Оба npm audit сообщают [GHSA-w9m9-85wc-3x92](https://github.com/advisories/GHSA-w9m9-85wc-3x92), Low, uncontrolled AST recursion. На дату проверки advisory указывает исправления 6.1.3 и 7.1.3; для текущей 6.x цепочки сначала проверить совместимое обновление до исправленного patch.

Достижимость через пользовательские данные приложения не установлена; обнаруженная цепочка относится к CSS tooling. Нельзя из одного audit делать вывод об удалённой эксплуатации в production. Пакеты и lockfile в ходе аудита не менялись.

**Действие:** целевое обновление lockfile с проверкой совместимости, повторить полный набор проверок и добавить dependency audit в CI с явной политикой для Low advisories. Не запускать слепое `npm audit fix --force`.

## Положительная часть security pass

Использован proportional API-security playbook: входные данные, авторизация, ошибки, хранение и ограничение ресурсов. В существующих BFF tests проверяются PKCE/identity validation, HttpOnly/Secure session cookie, Origin/CSRF checks, лимиты, запрет клиентского identity spoofing и отсутствие service token/private prompt в тестовых логах. Модели импортов проверяют ограничения размера/schema/координат; player-handout и media gates имеют focused coverage.

В просмотренной поверхности подтверждённых security Critical/High/Medium не найдено; это не pentest всей системы. Low advisory остаётся открытым. Коммерческие/IP gates и риски потери данных также не закрыты. Никаких находок не помечено исправленными этим аудитом.

- Production SSO, cookies/CORS на реальном домене, работа gateway, секреты/ротация и runtime configuration сервера.
- Полный импорт каждого реального PNG/JPEG/WebP/JSON файла через UI, PDF rendering, все комбинации player handout и все поля Reference Board wizard.
- Safari/Firefox, физический touch/stylus, screen reader, полный keyboard-only обход, нагрузка большого мира и сотен сессий.
- Работа нескольких вкладок, конкурентная запись/миграция storage и восстановление после аварийного завершения браузера.

## Рекомендуемый порядок следующих работ

1. **Надёжность мира:** A01–A04 вместе с storage migration и regression E2E. Готовность: reload, quota и две кампании больше не теряют/смешивают данные; undo действует только в нужном редакторе.
2. **Удобный Map Workspace:** A05–A06, отдельный редактируемый document на карту, полноразмерный холст, working geometry. Готовность: пользователь без инструкции рисует, сохраняет, закрывает и снова редактирует ту же карту на desktop/mobile.
3. **Ошибки, единый UX и provenance:** A08–A10, offline/cancel/retry, локализация, безопасный экспорт. Готовность: каждое действие имеет правдивый результат и понятное восстановление.
4. **Release readiness:** A07, A11–A12, cloud staging smoke без настоящих кампаний, security и branding review. Billing/marketing не открывать по результату одного локального аудита.

Слои, гексы, освещение, fog и расширенные возможности категории Dungeon Scrawl остаются разумным развитием, но после исправления основы сохранения и рабочего пространства. Следующее безопасное действие — отдельный bounded implementation slice A01–A04 с тестами; этот отчёт не является разрешением на push или изменением глобальных предпочтений пользователя.
